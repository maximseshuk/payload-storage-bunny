Bunny Stream handles video and audio: adaptive HLS/MP4 playback, thumbnails, and resumable uploads for large files. It is the `stream` block passed to `bunnyStorage(...)`.

```ts payload.config.ts
bunnyStorage({
  collections: { media: true },
  stream: {
    apiKey: process.env.BUNNY_STREAM_API_KEY!,
    hostname: process.env.BUNNY_STREAM_HOSTNAME!, // e.g. vz-xxxx.b-cdn.net
    libraryId: Number(process.env.BUNNY_STREAM_LIBRARY_ID),
    mp4Fallback: true,
  },
})
```

With Payload access control on (the default), a Stream collection needs `mp4Fallback: true` or signed URLs with redirect — otherwise the plugin throws at startup. See [Access control and mp4Fallback](/v4/configuration/stream/overview#access-control-and-mp4-fallback). Set `disablePayloadAccessControl: true` on the collection to serve straight from the CDN instead, where this requirement doesn't apply.

Files whose MIME type matches `mimeTypes` are routed to Bunny Stream. Everything else goes to [Bunny Storage](/v4/configuration/storage/overview), if configured. When a document gets a new file that goes to Bunny Storage, the plugin removes its Stream video ID. The old video then follows the rules in [Replaced videos and versions](#replaced-videos-and-versions). The plugin names a new video in Bunny after the uploaded file name, without Payload's `-original` suffix. The file URL and the admin thumbnail come from Bunny Stream when the document has a Stream video ID and its file is a video or audio file, matches `mimeTypes` or has no MIME type. Other files get the Bunny Storage URL. Video metadata for each document lives in the [`bunnyData`](/v4/guides/stored-data) field.

Default `mimeTypes` cover the common video and audio formats: MP4, MKV, WebM, FLV, AVI, MOV, WMV, MPEG, TS, MXF, and MP3/OGG/WAV audio.

<Info>

The top-level `stream` block is optional. If every collection points at [its own stream library](#collection-overrides), you can omit the global `stream` entirely.

</Info>

## Access control and MP4 fallback

By default, files are served through Payload's access control (`disablePayloadAccessControl` isn't set on the collection). For Stream videos in this mode, Bunny can't serve HLS directly through Payload's proxy, so you need one of:

- **`mp4Fallback: true`** — Payload proxies the MP4 rendition instead of HLS. When the stored `resolutions` are missing or wrong, the first request stores the rendition it found. Like the status writes, this goes straight to the database: it does not run your collection hooks, does not create a version and does not change `updatedAt`.
- **Signed URLs with redirect** — set `signedUrls.staticHandler.redirect: true` (globally or on the collection) so Payload redirects straight to Bunny's HLS stream instead of proxying it. This is the faster option — see [Signed URLs](/v4/configuration/signed-urls).

Without `mp4Fallback`, the redirect is the only way to serve the video. If `shouldUseSignedUrl` returns `false` for a file, there is no redirect, and the file route answers `400`.

<Warning>

The plugin's options validator rejects a collection at startup if neither is set and access control is on. If you set `disablePayloadAccessControl: true` on a collection instead, files are served directly from the Bunny CDN and this restriction doesn't apply.

</Warning>

When Payload proxies the MP4 fallback or a Stream thumbnail, it fetches the file from Bunny server-side. If your Stream library uses a BlockNoneReferrer rule, set [`referer`](#options) to a value the library allows so those requests aren't rejected. Default libraries need nothing here.

<Warning>

**Known limitation.** Without `mp4Fallback`, the redirect to the HLS playlist (`playlist.m3u8`) drops the query string of the file request. The MP4 fallback keeps it.

</Warning>

## Edit view player

The edit view of a Stream video or audio file shows the Bunny Stream player instead of Payload's built-in player, also with [TUS uploads](/v4/configuration/stream/tus). With `disablePayloadAccessControl: true`, Payload's own player gets the HLS playlist (`playlist.m3u8`) as the file URL and cannot play it outside Safari. With Payload access control on and `mp4Fallback`, it gets the MP4 file. While Bunny encodes the file, the preview shows a processing message and switches to the player when the file is ready. With `status: false` the player shows right away. Files without a Bunny Stream video ID and other file types keep Payload's own preview.

The plugin adds the player to the collection's `upload.admin.components.filePreview` for `video/*` and `audio/*`, but only for a category that has a type in the Stream `mimeTypes`. With `mimeTypes: ['video/mp4']`, it adds only `video/*`:

- A `filePreview` component, or a map with `*`, stays as it is. With `*` the map covers every file type, so the plugin adds nothing.
- In any other map, a `video/*` or `audio/*` entry that is already there stays, and the plugin adds the missing ones.

Payload runs everything in `plugins` before the adapters in `storage`, whatever the order of the `plugins` array. So the [media preview plugin](/v4/guides/media-preview) always sets its map first. The map has `*`, so this plugin adds nothing to it. With the media preview plugin, register the Bunny Stream adapter (`bunnyStreamAdapter`) in its `adapters`, and the adapter shows the player. Without the adapter, the media preview plugin sets `video/*` and `audio/*` to `false`, and Stream files get Payload's own player, which cannot play the HLS playlist outside Safari. The plugin logs a warning at startup when a Stream collection with `preview` on sets `video/*`, `audio/*` or one of its Stream `mimeTypes`, for example `video/mp4`, to `false`.

Set `preview: false` to turn the player off, globally or for one collection. The player is in the import map, so run `payload generate:importmap` after you upgrade.

<Warning>

**Known limitations.**

- When a video replaces an image, the edit view shows Payload's own video player until you reload the page. Payload picks the file preview from the MIME type when it loads the document.
- Payload's upload area renders a hidden crop image with the file URL of a video. While Bunny has no MP4 rendition yet, this request fails, and the browser console shows `404` errors. The upload is not affected.

</Warning>

## Replaced videos and versions

Stream videos follow the same rule as [files in Bunny Storage](/v4/configuration/storage/overview#files-versions-and-rename):

- **With `versions`** (the Payload 4 default), a replaced video stays in your Stream library while any document or version references it. So restoring a version brings back a working video. The video is deleted when no document and no version references it any more, in any collection that uses the same library. This includes versions that Payload removes because of `maxPerDoc`, and an autosave version that a new video replaces. Payload overwrites the autosave version of a draft in place, so the old video loses that reference on the next autosave.
- **With `versions: false`**, the old video is deleted when you replace it, as before. Set `versions: false` on the collection to get this behavior back.

Only operations through Payload delete videos: replacing the file, deleting a document, changing a draft and removing versions. Changes made directly in the database, for example with SQL or `payload.db.*`, do not delete videos.

Renaming a file (`payload.renameFile`, or the rename operation in REST and GraphQL) and restoring a version copy nothing in Stream. The old and the new key point to the same video.

## Cleanup

Some uploads leave videos in your library that no document uses. This happens when an upload stops halfway, for example after a closed tab or a failed TUS session. It also happens when the upload finishes but the document is never saved, for example when a bulk upload save fails. Enable `cleanup` to remove these videos on a schedule.

Cleanup only checks uploads that this plugin started. Before it deletes a fully uploaded video, it makes sure no document references it. It never touches videos that other services or the Bunny dashboard add to the same library. Keep `maxAge` longer than an editor might leave an upload unsaved, because a document saved after cleanup has run points to a deleted video.

```ts
stream: {
  // ...
  cleanup: true, // daily cleanup with defaults
}
```

Or customize:

```ts
stream: {
  cleanup: {
    maxAge: 86400,                              // seconds before an unsaved upload is considered dead (default)
    schedule: { cron: '0 2 * * *', queue: 'storage-bunny' }, // default: daily at 2am
  },
}
```

| Option     | Type     | Default                                         | Description                                               |
| ---------- | -------- | ----------------------------------------------- | --------------------------------------------------------- |
| `maxAge`   | `number` | `86400`                                         | Seconds after which an unsaved upload is considered dead. |
| `schedule` | object   | `{ cron: '0 2 * * *', queue: 'storage-bunny' }` | Cron schedule for the cleanup job.                        |

Cleanup registers a Payload job task. Something must run it: the Payload jobs runner, a cron call to the plugin's tasks endpoint, the `bunny:task` CLI or your own code. See [Background tasks](/v4/configuration/background-tasks).

<Info>

There is one cleanup task for the whole plugin, and its `schedule` is **global-only** — set it on the top-level `stream.cleanup`. When a collection points at its own library, its `cleanup` controls only `maxAge` (each library's stale sessions are swept with that library's own cutoff); it can't set a separate `schedule`.

</Info>

## Collection overrides

A collection's `stream` can be one of three things:

- a **partial override** (`mimeTypes`, `mp4Fallback`, `preview`, `status`, `thumbnailTime`, `tus`, `uploadTimeout`) — merged onto the global library;
- **full options** (with their own `apiKey`/`hostname`/`libraryId`) — this collection uses its OWN stream library, ignoring the global library entirely;
- **`false`** — disable Bunny Stream for this collection.

```ts
collections: {
  // Partial override — tweak the global library
  largeVideos: {
    stream: {
      mimeTypes: ['video/mp4'],  // narrow allowed types for this collection
      mp4Fallback: true,
      thumbnailTime: 3000,
      uploadTimeout: 600000,     // 10 minutes
      tus: {
        expiresIn: 7200,         // 2 hours
        autoMode: true,
      },
    },
  },
  // Full options — this collection uses its own library
  tenantA: {
    stream: {
      apiKey: process.env.TENANT_A_STREAM_API_KEY!,
      hostname: 'vz-tenant-a-123.b-cdn.net',
      libraryId: 654321,
      mp4Fallback: true,
      tokenSecurityKey: process.env.TENANT_A_STREAM_TOKEN_KEY, // for signed URLs on this library
      webhook: { secret: process.env.TENANT_A_STREAM_READONLY_API_KEY! }, // this library's Read-Only API key
      cleanup: { maxAge: 43200 }, // per-library cutoff; schedule stays global-only
    },
  },
  shortClips: {
    stream: {
      tus: false, // disable TUS for this collection only
    },
  },
  imagesOnly: {
    stream: false, // disable Bunny Stream for this collection — videos will fail to upload
  },
}
```

The plugin distinguishes full options from a partial override by whether it includes `apiKey`. Full options **inherit nothing** from the global library — `mimeTypes`, `mp4Fallback`, `tus`, and the rest fall back to plugin defaults, not the global library's values. Provide that library's own `tokenSecurityKey` for [signed URLs](/v4/configuration/signed-urls), and its own `webhook.secret` if you use webhooks. Per-collection `cleanup` carries only `maxAge`, and per-collection `status.sync` carries only `limit` and `maxAge`. Both schedules are global-only. With full options, `status.link` is `true` and status sync is off unless you set them.

A partial `tus: true` or `tus: { … }` turns TUS on for that collection, even when the global `stream.tus` is off. `tus: false` turns it off.

A partial `preview` turns the [edit view player](#edit-view-player) on or off for that collection.

See [Collection overrides](/v4/configuration/collection-overrides) for the full-options vs partial-override rules and the complete list of options.
