---
title: 'Thumbnails'
description: 'Populate a thumbnailURL field on upload documents for admin previews and API responses.'
---

`thumbnail` populates a hidden `thumbnailURL` field on your upload documents, which the admin panel uses to show a preview image in list and edit views, and which is available in every API response.

```ts payload.config.ts
bunnyStorage({
  collections: { media: true },
  storage: {/* ... */},
  thumbnail: true, // enable with defaults
})
```

- **Images** — uses the original file, or a specific variant if `sizeName` is set.
- **Bunny Stream videos** — uses the frame captured at [`stream.thumbnailTime`](/v4/configuration/stream/overview#options).

## Thumbnail URLs

With Payload access control on (the default), an image thumbnail URL is Payload's `<routes.api>/<collection>/file/<filename>`, with the variant's file name when `sizeName` is set. A Stream video thumbnail URL is the plugin's own endpoint, `<routes.api>/storage-bunny/stream/thumbnail/<collection>/<id>/<videoId>/thumbnail.jpg` (`preview.webp` with `streamAnimated`). `<routes.api>` is the API route of your Payload config, `/api` by default. The endpoint reads the document with Payload access control and fetches the image from the Stream CDN, so Payload [upload transformers](https://payloadcms.com/docs/upload/overview) never handle it. See the [API reference](/v4/api-reference/overview).

With `disablePayloadAccessControl: true`, both point straight at the Bunny CDN, signed when [`signedUrls`](/v4/configuration/signed-urls) is on.

`thumbnailURL` is computed each time a document is read, so it always has the current form.

## Options

| Option                         | Type                            | Default                     | Description                                                                                                                                                        |
| ------------------------------ | ------------------------------- | --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `sizeName`                     | `string`                        | –                           | Use a named image variant of your collection instead of the original file. Falls back to the original if the variant is missing on a given document.               |
| `streamAnimated`               | `boolean`                       | `false`                     | For Stream videos, use an animated WebP preview (`preview.webp`) instead of a static JPEG (`thumbnail.jpg`).                                                       |
| `urlTransform`                 | `boolean \| object \| function` | `{ appendTimestamp: true }` | Same forms as [`urlTransform`](/v4/configuration/url-transforms), applied to the thumbnail URL. `false` turns the transform off.                                   |
| `urlTransform.appendTimestamp` | `boolean`                       | `true`                      | Append a `t=<timestamp>` query parameter so browsers fetch the latest thumbnail after a file changes.                                                              |
| `urlTransform.queryParams`     | `Record<string, string>`        | `{}`                        | Static query parameters appended to the thumbnail URL — handy for [Bunny's Image Optimizer](https://docs.bunny.net/docs/stream-image-optimization?ref=fndfoymy0j). |

## Cache-busting with appendTimestamp

Thumbnails have `urlTransform.appendTimestamp` **on by default**. When a file is replaced (for example, during image cropping), the timestamp changes and browsers fetch the new version instead of a cached copy. While it is enabled, the plugin also disables Payload's cache tags for the thumbnail field, to avoid caching conflicts.

Opt out in the options if you don't want it:

```ts
thumbnail: {
  urlTransform: { appendTimestamp: false },
}
```

<Tip>
To make this effective on Bunny's side too, go to your Pull Zone → **Caching** → enable **Vary Cache** for **URL Query String**, and add `t` to the vary parameter list.

If you need immediate cache invalidation everywhere instead of relying on the browser refetching, use [cache purging](/v4/configuration/cache-purge).

</Tip>

## Resizing with queryParams

```ts
thumbnail: {
  urlTransform: {
    queryParams: {
      width: '300',
      height: '300',
      quality: '85',
    },
  },
}
```

With Payload access control on and Sharp [dynamic resizing](/v4/configuration/url-transforms#sharp-dynamic-resizing) turned on, Sharp takes an image thumbnail request when its URL has a `width`, `height` or `withoutEnlargement` parameter. It then resizes the image on your server, and none of the parameters reach Bunny. Stream video thumbnails always send them to Bunny.

## Using a named image size

```ts
thumbnail: {
  sizeName: 'thumbnail',
}
```

`sizeName` is the name of a variant that `sharpTransformer({ collections: { <slug>: { variants } } })` from `@payloadcms/transformer-sharp` generates for the collection.

## Custom transform function

For full control over the thumbnail URL, pass a function as `thumbnail.urlTransform`. It replaces `appendTimestamp` and `queryParams`, and you build the URL yourself. `sizeName` and `streamAnimated` still apply.

```ts
thumbnail: {
  sizeName: 'thumbnail',
  urlTransform: ({ baseUrl }) => `${baseUrl}?class=thumb`,
}
```

The function receives the same arguments as the [`urlTransform` function](/v4/configuration/url-transforms#custom-transform-function) (`baseUrl`, `collection`, `filename`, `prefix`, `data`) and returns the final URL string.

## Collection overrides

```ts
collections: {
  gallery: {
    thumbnail: {
      sizeName: 'thumbnail',
    },
  },
  documents: {
    thumbnail: false, // no thumbnails for this collection
  },
}
```

A collection `thumbnail` keeps the global `thumbnail.urlTransform` unless it sets its own. A collection `thumbnail.urlTransform` object merges onto a global object and replaces a global function.

See [Collection overrides](/v4/configuration/collection-overrides) for the full list of options you can tune per collection.
